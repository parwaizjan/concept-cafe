# Architecture

## Stack

| Concern   | Choice                                                | Notes                                                              |
| --------- | ----------------------------------------------------- | ------------------------------------------------------------------ |
| Framework | **Astro 7** (`7.3.5`)                                 | Static-first, island-free content site.                            |
| Styling   | **Tailwind CSS v4** (`4.3.3`) via `@tailwindcss/vite` | Design tokens as CSS variables / `@theme inline`.                  |
| Adapter   | **`@astrojs/cloudflare`** (`14.3.3`)                  | `output: 'static'`, `session: false`, `imageService: 'compile'`.   |
| i18n      | **Astro built-in i18n layout** + `src/i18n/ui.ts`     | English enabled; `si`/`ta` structured but off.                     |
| Fonts     | **Fontsource variable**, self-hosted                  | Newsreader (display) + Figtree (body) + Noto Sinhala/Tamil stacks. |
| SEO       | **`@astrojs/sitemap`** (`3.7.4`)                      | Enabled only when `indexable` is true.                             |
| Content   | **Astro Content Collections** + Google Sheet          | Menu/categories in `src/content/*`; live prices from Sheet.        |
| Runtime   | **Cloudflare Workers**                                | Git-connected Workers Builds; static assets only.                  |
| Toolchain | **Node 22**, **pnpm 12**, **TypeScript 6**            | See `DECISIONS.md` D-C03.                                          |

### Build output (Astro 7 + adapter v14)

- `astro build` emits static assets to `dist/client/`; `dist/server/` is empty for
  this all-static site.
- The adapter generates `dist/client/wrangler.json` plus a `.wrangler/deploy/config.json`
  redirect, so `wrangler deploy` from the repo root uses the generated config. The
  root `wrangler.jsonc` only needs `name`, compatibility settings, `main`,
  `assets.not_found_handling`, and optional bindings.
- `session: false` avoids provisioning a session KV namespace.
- `imageService: 'compile'` optimizes imported content images at build time
  (Sharp → WebP variants) without needing the Cloudflare Images binding. The
  full-bleed hero uses pre-sized WebP via a CSS background.
- Dev and preview run on the real `workerd` runtime.

## Static vs on-demand

All pages are prerendered, including `robots.txt.ts`. There are **no** on-demand
routes, no bindings, no database and no email. WhatsApp enquiries are deep links
only. Sheet data is fetched either in the browser (runtime) or at build time
(build), never by a request-time server.

## Content model (`src/content.config.ts`)

```ts
const localizedText = z.object({
  en: z.string(),
  si: z.string().optional(),
  ta: z.string().optional(),
});

const menu = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/menu" }),
  schema: z.object({
    category: z.string(), // category id
    name: localizedText,
    description: localizedText.optional(),
    price: z.number().nonnegative(), // LKR, overridden by the Sheet
    available: z.boolean().default(true),
    veg: z.boolean().default(false),
    special: z.boolean().default(false), // drives what's-on / specials
    featured: z.boolean().default(false), // shown in the home signature strip
    order: z.number().default(0),
    image: z.string().optional(),
  }),
});

const categories = defineCollection({
  loader: glob({ pattern: "**/*.md", base: "./src/content/categories" }),
  schema: z.object({
    name: localizedText,
    description: localizedText.optional(),
    order: z.number().default(0),
  }),
});

export const collections = { menu, categories };
```

The **item file name (without `.md`) is the stable id** that matches rows in the
owner's Google Sheet, so renames must be deliberate. See
`docs/CONTENT-AND-MENU.md`.

## Data flow

```
content collections ─┐
                     ├─▶ lib/menu.ts ─▶ pages/components ─▶ HTML
Google Sheet (live) ─┘         │
                               └─▶ client menu script (runtime mode)
```

- `lib/menu.ts` is the only place that knows about both sources. It merges
  collection data with Sheet overrides by id (price/available/special), groups by
  category, and exposes query helpers (`getItems`, `getCategories`, `getFeatured`,
  `getSpecials`).
- In `runtime` mode, `MenuList`/`SpecialsStrip` render `data-*` hooks and a small
  client script re-fetches the Sheet in the browser to refresh price/availability/
  special; failures fall back to the build-time values.
- In `build` mode (production clones), `scripts/fetch-menu.ts` fetches the Sheet
  during `prebuild` and writes `src/data/menu-live.json`; the site is fully static
  and the Sheet is never requested at runtime.

## i18n strategy

- Astro i18n is configured with `defaultLocale` and `locales: [...site.locales]`,
  `prefixDefaultLocale: false`. English is served at `/`; enabling `si`/`ta` adds
  generated `/si/…` and `/ta/…` routes with no component changes.
- All UI strings live in `src/i18n/ui.ts` in parallel `en`/`si`/`ta` objects.
  `useTranslations(locale)` is typed against `en`, so missing `si`/`ta` keys fall
  back to English at runtime and structural drift is a type concern.
- Localized content fields use `LocalizedText`; a missing `si`/`ta` value falls back
  to `en`.
- `localizePath(path, locale)` / `switchLocalePath(pathname, target)` build links;
  `LangSwitcher` links to the same page in every enabled locale and is hidden when
  only one locale is enabled.
- `BaseLayout` emits `hreflang` alternates and `og:locale` for every enabled locale.
- WhatsApp pre-filled messages and the directions link are localized where useful.

## Theming

Tokens live in `src/styles/theme.css`; `global.css` maps them to Tailwind via
`@theme inline`. A clone rebrands by editing token values (and preset overrides)
only.

| -------------------- | ------------ | ------------------------------- |
| `--c-bg`             | `#FBF7EF`    | Warm cream page canvas          |
| `--c-surface`        | `#FFFFFF`    | Cards / raised panels           |
| `--c-surface-alt`    | `#F2EADD`    | Subtle section background       |
| `--c-text`           | `#2B2620`    | Primary text (warm near-black)  |
| `--c-text-muted`     | `#766A5B`    | Secondary text                  |
| `--c-primary`        | `#4A342A`    | Espresso — buttons              |

`border-border`, `bg-primary`, `text-primary`, `bg-accent`; `font-heading`,
`font-body`. Radius is moderate (`--radius-md`), shadows soft. Reusable classes:
`.eyebrow`, `.btn-primary`, `.btn-outline`, `.card`, `.price-leader` (the dotted
menu leader).

Fonts are loaded via Fontsource variable; both stacks include Noto Sans Sinhala and
Noto Sans Tamil so Indic text renders correctly once translations are enabled.

## Components

- `SampleRibbon` — slim, non-dismissible brand-tinted strip above the header with
  the "sample website" note and a "Message us" link (demo only).
- `Header` — logo, anchor nav (Menu, Gallery, What's-on, Visit), **Get directions**
  CTA, `LangSwitcher`.
- `Footer` — brand, anchor nav, socials, hours summary, address, "Message us",
  copyright.
- `CafeHero` — editorial hero with atmosphere image, brand, tagline and the two
  primary CTAs (View the menu, Get directions).
- `menu/*` — sticky `CategoryTabs`, coffee-house `MenuList`/`MenuItem` with dotted
  leaders, `DietaryBadges` (veg), `SpecialsStrip`, `SignatureItems` (featured items
  via `MediaImage`).
- `gallery/GalleryGrid` — responsive roomy image grid.
- `whatson/WhatsOnList` — specials/seasonal items and small events.
- `visit/*` — address, hours, map embed and one-tap directions.
- `reviews/Reviews` — invented short quotes.
- `ContactSection` — the "Message us" enquiry form (topic chips + name + note)
  and the paid-add-ons hint.
- `pages/HomePage.astro` composes the single page.
- Guidelines: semantic HTML, accessible labels/focus states, mobile-first, no
  hardcoded brand values, no client framework islands.

The only shipped JavaScript is `src/scripts/menu.ts` (runtime Sheet refresh) plus a
tiny inline mobile-nav toggle. Both degrade gracefully without JS.

## WhatsApp & directions links

- `src/lib/whatsapp.ts` exports `buildWhatsAppUrl(message, number?)`:

  ```ts
  const n = number.replace(/\D/g, "");
  return `https://wa.me/${n}?text=${encodeURIComponent(message)}`;
  ```

- `src/lib/contact.ts` assembles the "message us" enquiry text from a topic key and
  optional free-text note. Never label it "Order now".
- `src/lib/directions.ts` builds `https://www.google.com/maps/dir/?api=1&destination=<lat>,<lng>`
  from `site.geo` (falling back to the address). Never inline `maps.google.com` or
  `wa.me` URLs in components.

## SEO & structured data

- `BaseLayout` emits `<title>`, meta description, canonical (`Astro.url` /
  `site.siteUrl`), OG/Twitter tags and `og:image`.
- `@astrojs/sitemap` is added only when `site.indexable` is true.
- JSON-LD: `CafeOrCoffeeShop` (`LocalBusiness`) with name, address, geo, opening
  hours, `servesCuisine`, `priceRange`, `sameAs` socials and `hasMenu` pointing at
  the home page's `#menu` anchor. See `docs/DISCOVERY-AND-CONTACT.md`.
- `404.astro` + `assets.not_found_handling: "404-page"` in `wrangler.jsonc`.

## Indexing

`site.indexable` drives `BaseLayout` (`<meta name="robots">`) and `robots.txt.ts`;
`public/_headers` sends `X-Robots-Tag: noindex` on the demo. The demo ships `false`;
clones flip all three. See `docs/CUSTOMIZATION.md`.
